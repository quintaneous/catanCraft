# ECO-03 — bounded voluntary pickup exits, 047

This change addresses the 046 finding that all eight pinned SBW pickup seat exits overlap the vehicle's native Collision OBB. It does not change SBW data, ordinary vehicles, vehicle delivery, prices, purchases, or the 046 provider-baseline tests. Existing `CatanCraftPurchasedVehicle=true` plus a valid nonzero `CatanCraftVehicleNation` UUID and exact type `superbwarfare:sodayo_pick_up` scope the correction. These tags identify vehicles needing egress protection; they are not purchase, payment, or journal authority. Existing marked pickups require no migration. Other vehicle types, including LAV, remain on their provider path.

The pinned SBW 0.8.9.2 source establishes the actual voluntary path:

- `mixins/PlayerMixin.java` suppresses `Player.wantsToStopRiding` for a `VehicleEntity`, so ordinary Shift dismount is disabled by the provider.
- `event/ClickEventHandler.kt` sends `PlayerStopRidingMessage(false)` for its dismount key. Ejection sends `true` separately.
- `network/PacketPayload.kt` defines `PayloadContext` as `Supplier<NetworkEvent.Context>` and enqueues its handler on the server thread.
- The false-ejection packet normally calls `player.stopRiding`, clears jumping, and grants ten ticks of the provider's strike-protection effect.
- `VehicleEntity.getDismountLocationForPassenger` reads the saved seat tag and returns `getDismountLocationForIndex`. Explicit pickup positions are final, not candidates that receive a later SBW safety adjustment. The provider's living-entity mixin removes the saved seat tag after native dismount completion.

`SbwVoluntaryExit47Mixin` intercepts the exact `handler(Ljava/util/function/Supplier;)V` descriptor. `SbwVehicleDismount47Mixin` intercepts only the provider-owned indexed final-exit method. Both use `@Pseudo` for an absent optional provider and `require=1` when that provider is present; a changed present handler must not silently fall through to the unsafe baseline. No general `stopRiding`, death, command, forced-unload or ejection hook is cancelled.

The voluntary handler verifies a living passenger and vehicle, server-thread execution, the current native seat/tag agreement, finite pose and motion, an upright vehicle moving at no more than 0.01 blocks per tick, and the pinned effective pickup JSON SHA-256 `b53ee2f4cb22708e68decf7af5a26ddb8587d88303f8400c47b32c0b5c22841a`. Every vertex and part of all eight actual native OBBs must match the frozen pickup geometry at its current pose within 0.0001; every native seat exit must match its pinned transform too. This rejects per-entity modified/stale geometry even if the resource file is unchanged. A missing final-exit hook acknowledgement refuses before removal. The resolver never sets vehicle position or runs vehicle physics.

The search is limited to four offsets, 0.125, 0.25, 0.375 and 0.5 block, directly outward from the current seat's native exit. Side seats use their original side; rear seats use the rear. It does not search around the player, switch to the opposite side, or teleport to a remote empty location. Landing feet are at the integer block-top level directly below the native exit, with a downward change strictly less than one block. The entire 0.6-wide standing footprint must have full-block, nonfluid support. The full 1.8-high standing body plus its complete downward landing sweep must clear actual block collision shapes, fluid, other entities and native SAT against every own vehicle OBB. All vehicle OBB footprints retain current collision/fluid/entity and full-support checks. Probes are limited to the already-loaded block-and-entity neighborhood within seven blocks horizontally and from the vehicle floor minus one to plus four vertically, inside build height and the world border. No chunk loading, terrain fabrication, air clearing, or world repair is performed by the resolver.

If all candidates fail, the packet is consumed while the passenger remains in the same seat and position. The message asks the player to clear space, or to stop on level ground when moving/tilted. An accepted attempt holds its candidate only in thread-local scope around that single native `stopRiding`, with `try/finally` cleanup. Only its exact vehicle, passenger and seat can obtain the override; UUID, position and pose are checked again at use. The native packet's ordinary post-success jumping/effect behavior is retained. Forced/ejection/death/direct calls never receive the override.

A scoped LOWEST-priority Forge mount-event listener rechecks the active voluntary attempt before the riding link is cleared, and can cancel if another earlier event handler introduces a hazard. It respects cancellation by another handler. This listener does nothing without the matching explicit voluntary attempt. The official [Forge 1.20.1 Entity patch](https://github.com/MinecraftForge/MinecraftForge/blob/1.20.1/patches/minecraft/net/minecraft/world/entity/Entity.java.patch) and [EntityMountEvent](https://github.com/MinecraftForge/MinecraftForge/blob/1.20.1/src/main/java/net/minecraftforge/event/entity/EntityMountEvent.java) document cancellation before removal; these are branch-source evidence, not an independently pinned 47.4.10 artifact. The attempted exact Maven source JAR request returned HTTP403 and the guessed version Git tag did not exist. The native test proves the actual pinned-runtime ordering separately. Arbitrary other-mod mutation after the final recheck is not certified by this batch; installed-pack acceptance remains separate.

There are six new cases in `catancraft_vehicle47_exit`, each restricted to the exact no-player `controlled-catancraft_vehicle47_exit-run/world` fixture. Each stages the same 18,400-cell unchanged authored starter/factory slice as 046. Every seat is boarded through the actual native API at rotations 0/180, and the real packet handler is invoked with a real Forge context backed by a fake player's packet listener. Tests require actual removal and the checked final position, then recheck that the unscoped provider baseline still overlaps its own OBB. The other cases require packet refusals for stone, fluid, missing footprint support, entity occupancy, modified non-primary OBB geometry, movement, NaN motion, wrong seat tag, stale pose and unloaded neighborhoods; they also exercise retry, ordinary/other-vehicle/forced/ejection/dead-passenger bypass, an event-time obstacle, and cancellation by another Forge listener. Existing authored posts/lanterns remain unchanged.

Expected evidence markers are sixteen `VEHICLE47_EXIT_SEAT_PASS`, two `VEHICLE47_EXIT_ALL_SEATS_PASS`, and one each of `VEHICLE47_EXIT_HAZARDS_PASS`, `VEHICLE47_EXIT_BYPASS_PASS`, `VEHICLE47_EXIT_IDENTITY_PASS`, and `VEHICLE47_EXIT_FORGE_PASS`. Markers are emitted only after their assertions. Source construction and static checks are not a build or native test pass; the root validation report must retain exact source, logs, executed/passed/failed counts and any failures. No in-game owner acceptance, full driving/turning qualification, vehicle-shop activation, multiplayer test or SEC-01 crowbar acceptance follows from this work.

The follow-up residency guard requires both `hasChunkAt` and `ServerLevel.areEntitiesLoaded` for every checked cell's chunk before consulting occupancy. A resident block chunk alone is insufficient: the official Forge 1.20.1 `PersistentEntitySectionManager` patch shows queued entity loads being added before the chunk status becomes `LOADED`. This is branch-source evidence, not a reproduced persisted-entity bypass or a separately retrieved 47.4.10 implementation. Production merely refuses and does not acquire tickets or load chunks.

The same six native exit cases now stage their authored cells exactly once, acquire a bounded fixture-only `SectorChunkLease`, and use five-tick asynchronous retries (maximum 400 ticks) to await genuine block and entity residency. They assert readiness before their existing test bodies and release tickets on success or failure. A pre-wait observation directly asserts guard refusal only if it actually sees a resident block chunk with entity loading incomplete; it never rewrites entity-manager state to manufacture that condition. `VEHICLE47_EXIT_RESIDENCY_PENDING_PASS` is emitted only for an observed and rejected pending state; otherwise the observation explicitly says the condition was not observed. Six `VEHICLE47_EXIT_RESIDENCY_READY` markers record the ready chunk counts and wait ticks. Existing six-case outcome markers are preserved. The official Forge 1.20.1 branch `NetworkEvent.Context` source includes the test's `(Connection, NetworkDirection, int)` constructor; its exact 47.4.10 runtime availability remains verified by constructing it in the native packet tests, not by an unavailable local pinned Forge source/class artifact.
